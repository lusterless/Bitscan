# Code Style Guidelines
- Use functional components and hooks; avoid class components.
- Always implement explicit type definitions—do not use 'any'.
- Use descriptive naming conventions for API endpoints (`/api/v1/...`).
- Python: 3.12, type hints everywhere, mypy --strict, ruff (lint + format). No business logic in route handlers. Pydantic v2 models for every request/response; no Any/untyped dict across layer boundaries.
- Go: gofmt, golangci-lint, no CGO, context-aware cancellation, errors wrapped with %w, table-driven tests.
- TypeScript: strict mode, ESLint + Prettier, generated OpenAPI client, no any.

# Guardrails & Restrictions
- Do NOT install separate UI component frameworks without asking.
- Always run unit tests after modifying any logic to verify code stability.
- Do not edit files outside the /src directory.
- Always run npm run lint or npm test or pytests or related lint and tests after modifying any logic to verify code stability.
- Never add a code path that pushes commands to agents, queues an ad-hoc command, or disables inventory collection.
- Never store a raw token or password; store only SHA-256 hashes (tokens) or Argon2id (passwords).
- Never parse untrusted XML without defusedxml; never evaluate catalog regex with a backtracking engine.
