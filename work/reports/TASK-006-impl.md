# TASK-006 IMPL: generated API client from `manager/openapi.json`

REQ-015, REQ-007. Spec: TS §6 (one API at `/api/v1`, OpenAPI 3.1 generated from code), TS §6.3 (no CORS, CSP `'self'`), TS §8.2 ("generated API client from OpenAPI"); `.claude/rules/web-ui.md` line 10; decision PD-14 (`openapi-typescript` + `openapi-fetch`, `manager/openapi.json`).

## Files
- `web/package.json`:
  - adds the script `gen:api`: `openapi-typescript ../manager/openapi.json --output src/api/schema.d.ts && prettier --write src/api/schema.d.ts`. Prettier makes the output match `format:check`, with LF endings;
  - adds `openapi-fetch` 0.17.0 (runtime dependency) and `openapi-typescript` 7.13.0 (dev dependency), pinned exactly;
  - **changes `typescript` from 6.0.3 to 5.9.3** (see below).
- `web/package-lock.json`: regenerated with `npm install`. It now has 165 packages, all from `registry.npmjs.org` with integrity hashes. This file is generated; the task row counts it as "+1 generated".
- `web/src/api/schema.d.ts`: generated by `npm run gen:api` from the committed `manager/openapi.json`, which has empty `paths`. Never edit it by hand.
- `web/src/api/client.ts` (6 lines): `export const api = createClient<paths>({ baseUrl: "" })`. With an empty `baseUrl`, every request is a relative URL on the page's own origin. There is no absolute origin: a grep for `https?:` or `//host` in the file finds nothing.

## TypeScript pin change (6.0.3 to 5.9.3)
`main` accepted this change and recorded it in `work/decisions.md`.

`openapi-typescript` 7.13.0 (npm `latest`; there is no newer major) declares the peer `typescript: ^5.x`. `typescript-eslint` 8.71.2 declares `>=4.8.4 <6.1.0`. 5.9.3, the newest 5.x, is the only TypeScript version inside both declared ranges. Keeping 6.0.3 would need an npm `overrides` entry that runs openapi-typescript outside its supported range. I chose the supported range instead. `npm ls typescript` shows a single deduped 5.9.3. I re-ran the TASK-005 typecheck plants with 5.9.3, and both are still red (exit 2: TS2322, TS7006). Revisit the pin when openapi-typescript supports TypeScript 6 or later.

## Base URL assumption
`baseUrl: ""` assumes the manager's OpenAPI `paths` carry the full `/api/v1/...` prefix, i.e. the routers are mounted with that prefix. M0 has no paths, so this cannot be checked yet. If the manager emits paths without the prefix, `baseUrl` becomes `"/api/v1"` (still same-origin). Check this when the first route lands in M3. `main` recorded this as an M3 recheck. Same-origin serving is still open question #6.
