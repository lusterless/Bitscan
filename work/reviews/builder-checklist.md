# Builder checklist (read before every hand-off)

Owner: reviewer. Each line is a finding that came back more than once in review. Fix it before handing off, not after. Format: rule | why | how to check.

## Input that reaches the database
1. Validate every client value before PostgreSQL casts it (`inet`, `cidr`, `jsonb`, `text`, `debversion`), and before any other step that serialises it (an idempotency digest, a hash). | Postgres refuses IPv6 zones (`%eth0`), U+0000, lone surrogates and `NaN`/`Infinity`, so the answer is a 500 instead of a 400 (TASK-048, 066, 067, 069). `json.dumps(allow_nan=False)` raises on a NaN the JSON parser accepted (TASK-205 r1). | Send `fe80::1%eth0`, `"\u0000"`, `"\ud800"` and `NaN` to each new field and expect 400.
2. Never compare Debian versions as text. | Text order puts `1.10` before `1.9` (TASK-053). | Grep the new SQL for `version` in `ORDER BY`, `>` or `<`; each must use `::debversion`.
3. Keep integer bounds in the OpenAPI document at or below 2^53 − 1. | FastAPI writes bounds as floats, so 2^63 − 1 becomes 2^63 (TASK-048 r2). | The re-exported `maximum` equals the model's bound exactly.
16. Any `audit_log.target` is cut to 255 characters (TS §5.2 `target VARCHAR(255)`); keep the full value in `detail`. | A file path used as a target can exceed 255 characters (a 255-byte name under `uploaded/`), and the failed INSERT loses the whole transaction, including the `bit_import` record (TASK-153). | Test each target built from a name or path with a 300-character value: the entry is written, the target is at most 255 characters, and the detail holds the full value.

## Order of checks on a route
4. Run the token check, or the per-IP limit, before FastAPI parses the body. | FastAPI parses a declared body before any dependency, so a bad body is answered uncounted and before authentication (TASK-067, 072, 082, 083). | Either use the `limit_first` route class or read the body yourself after the check. Test: a bad token plus a non-JSON body gets 401 and is counted.
5. Agent path and query ids accept only the hyphenated 8-4-4-4-12 form. | `uuid.UUID` also accepts the 32-hex, `{…}` and `urn:` forms (TASK-073, 083). | Use `agent_uuid()`. Test: the 32-hex form gets 400.
6. Compare protocol tokens (`Content-Encoding`, schemes) case-insensitively. | RFC 9110 says they are case-insensitive (TASK-073). | Test: `GZIP` is accepted.

## Concurrency and state
7. Mark an in-memory alert window as fired only on commit, and build it once per process. | Marking before commit loses the alert when the transaction rolls back. Building it per request resets the count (TASK-063, 064, 067). | Use `count_and_check` (or `due`) and register the mark with `tx.on_commit`. Build the window in `create_app()` or the runner.
8. For "once only" writes, use a conditional UPDATE and write the audit entry only when the UPDATE changed a row. | Two concurrent calls each wrote an entry (TASK-066). | `UPDATE … WHERE <state> RETURNING` or a `rowcount == 1` check. Test with two threads held at a barrier.
9. Decide from state re-read under the row lock, not from what an earlier check returned. | Concurrent rotations and twin enrolment requests acted on stale state (TASK-070, 075); a rebuild acted on a task row that start-up had already failed while it waited for the lock (TASK-157 r2). | Ask: what if another request changed this row while I waited for the lock?
10. Every loop that opens database transactions must honour stop. | The scheduler held `SIGTERM` for 46 s on a dead database (TASK-071). | Test: stop with the database refusing returns within the G27 bound.
18. Report or log a file step (removed, renamed, moved) only after the call succeeded, and never treat a file that will appear after the commit as missing inside the transaction. | A leftover was logged as removed after a failed unlink (TASK-156), and listed in `removed_leftovers` before its unlink (TASK-157). A rebuild deleted the policy it had just imported, because that policy's upload file is renamed into place only after the commit (TASK-157 r0, blocking). | For each file step, check that the success line or list entry comes after the call. For each in-transaction disk check, ask which files this transaction stages for after its commit. Test: make the unlink or rename fail, and import a new `uploaded/` file in the same transaction as a gone-file pass.
20. A background step that handles many rows must isolate each row (its own savepoint or transaction), so one bad row is logged and skipped rather than failing the step every run. | The deadline sweep rolled back for the whole fleet on one unreadable `eval_spec`, and since candidates come oldest first, the same row came first on every sweep (TASK-202 r0). The schedule tick needed the same per-row isolation (TASK-203). | Plant one bad row (owner write) next to a good one: the good one is processed in the same run, and the bad one is logged with its id and exception type only.

## Secrets and output
11. Keep tokens, token hashes, header values, request bodies, stdout, stderr and package lists out of logs, audit details, error text and `repr`. | TS §8.4 and the security invariants. | Run a canary test: plant a value and grep the logs, the audit rows and the response bodies for it.
12. Problem `detail` and log text never echo client input. Use fixed words only. | REQ-038 and #59. | Grep the new code for f-strings that build a `detail` from request data.

## OpenAPI
13. Re-export `manager/openapi.json`, keep it byte-stable, and avoid component-name clashes and 422s. A self-read body must still be documented. | G6 and REQ-060 (TASK-067, 073, 076). | Export twice and compare the two files.

## Go agent
14. Check the file type before opening any path the agent reads from configuration or the host (`ca_file`, `/etc/machine-id`, `/etc/os-release`, `/proc` files), and open non-blocking. | Opening a FIFO for reading blocks until a writer appears, so start-up or collection hangs (TASK-087 FAIL r1; same pattern noted in TASK-089 and TASK-098). | `os.Stat` → `IsRegular()`, then `O_RDONLY|O_NONBLOCK`, then `f.Stat()` again (see `config.readableFile`). Test: a FIFO at the path returns an error at once.
22. Any chmod, chown or other path call the runner makes inside a tree a plugin can write (its temp directory, the private `/tmp`, the delegated cgroup tree) goes through an `os.Root` or an `openat` with `O_NOFOLLOW`, never a plain path. | `unix.Chmod(path)` follows symlinks in every path component, so a parallel plugin of the same job could swap a directory for a symlink and redirect the call outside the tree (TASK-221 r0 should-fix). | Grep the runner for `os.Chmod`, `unix.Chmod`, `os.Chown`, `os.Lchown` and path-based `os.Remove` outside `os.Root`. Test: swap a subdirectory for a symlink to a runner-owned directory outside the tree, and its mode is unchanged.

## Builds, CI and runbooks
15. Give every local build or install target to pip as a path (`./manager`, `./x.whl`), and add `--no-index` when nothing should be downloaded. | In a non-editable `pip wheel` or `pip install`, a bare folder name is resolved as a PyPI requirement. The release job fetched the unrelated `Manager-2.0.5` sdist, and under `--no-build-isolation` its build hooks would run (TASK-135 r1, CHK-M6-112). | Grep the workflows, runbooks and scripts for `pip (wheel|install)` whose target has no `./`, `/`, `-r` or `-e`. `check_release_workflow.py` flags a `pip wheel` without `--no-index`.
16. Retry any status or readiness check that runs straight after `systemctl start`, `restart` or `enable --now`. | The command returns when the process starts, not when it listens, so a single `curl …/readyz` fails with "couldn't connect" (TASK-133 r1 CHK-M6-050; TASK-134 r2 F3). | Use the bounded retry loop from `manager-install.md` §9: 10 tries a second apart, stopping at the first HTTP answer so a 503 body still prints. Test: the walk runs the step exactly as written on a fresh host.
17. CLI sign-in with a secret: check the CLI doesn't print the secret back (e.g. `bao login -no-print`); a hidden prompt alone isn't enough. | `bao login` hid the typed token but printed it in its success table, so it would land on the manager host's screen and scrollback (TASK-133 r2c, CHK-M6-133r2-33). | Run the sign-in step as written under a pty that types a known secret, and count its occurrences in the captured output: it must be 0.

## Tests
19. Give `pytest.mark.parametrize` short explicit `ids=` whenever a parameter is a long string (over about 1,000 characters). | pytest writes the test id into `PYTEST_CURRENT_TEST`; on Windows an environment value over 32,767 characters raises at setup and teardown, so a local G66 run errors (TASK-190: `test_intake_plan.py`, `test_job_build.py`). | Run the new unit files once on Windows before the hand-off.
21. Run real-kernel and `systemd-run` rows as the unit's own user, with the unit's capabilities and `NoNewPrivileges`, not as root. Record the identity in the evidence. | Root passes every cgroup-delegation, `pidfd` and file-mode check regardless of ownership, so a root run can't show the failure the real `User=bitscan-runner` would hit (TASK-215 r0, the only real-kernel cover while the VM rows are NOT RUN). | `systemd-run -p Delegate=yes -p User=bitscan-runner -p Group=bitscan-runner -p AmbientCapabilities=CAP_DAC_READ_SEARCH -p CapabilityBoundingSet=CAP_DAC_READ_SEARCH -p NoNewPrivileges=yes …`; the test logs `uid` and `CapEff`/`CapBnd`.
