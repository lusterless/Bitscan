## cramfs sample (both `bits/samples/*.bit`, 1.1.1.1)
No finding.
- The plugin is read-only and BIT102-safe: it uses `grep`, `ls` and `find`, with redirects only to `/dev/null`.
- The fallback is correct. It reads `linux-modules*-$k.list`, which covers both `linux-modules-` and `linux-modules-extra-`, and kernel packages have no `:arch` suffix.
- It prints `unknown` only when neither `/lib/modules/$k/kernel` nor any module list is visible. Under `ProtectKernelModules=yes` with the lists present, it reports the real state.
- `unknown` does not match `^(absent|loaded=no install=yes blacklist=yes)$`, so it FAILs as intended.
- The two samples differ only in the expected name and id lines.

## Findings

1. **blocking**: `agent/test/sandbox/sandbox.py:41` and `:991`.
   - **Problem:** the harness parses `.bit` files with `xml.etree.ElementTree`, and the `# noqa: S405` / `S314` comments suppress the warning on purpose.
   - **Rule broken:** `.claude/rules/security-invariants.md` "Parse XML only with `defusedxml`: no DTD and no external entities (TS §4.1)". The invariants apply to all code, and the repo's other test code that reads samples already uses `defusedxml` (`manager/tests/test_bits_samples_pg.py:23,64`). The input here is repo-owned, so the real risk is low, but the rule has no test-code carve-out, and `--samples` takes any directory.
   - **Fix:**
     - install `python3-defusedxml` in `run_vm.sh` when `--samples` is given (the Ubuntu archive has it for 22.04 and 24.04);
     - use `from defusedxml import ElementTree as ET` and `ET.parse(f, forbid_dtd=True)`;
     - remove both `noqa` comments.
   - **Alternative:** the user records an explicit exception for the harness in `work/decisions.md`.

2. **should-fix**: `agent/test/sandbox/sandbox.py:1296–1302` (`write_report`, `--expect-red`).
   - **Problem:** when a plant names no `@part`, any FAIL counts as "red", including a row that crashed (`"suite error: …"`, set at `:1340`). These plants have no part: 325, 327, 329, 344, 386 and 389 (`sandbox.yml:130–132, 146, 151, 153`). A plant that only makes the harness throw, for example `res["results"][0]` indexing into a cut-short reply, would pass as "plant caught" without its check ever failing.
   - **Rule broken:** REQ-262 (1), "each VM plant turns its row red", and `.claude/rules/testing.md`, "do not lower a gate".
   - **Fix:** in `write_report`, treat a row whose evidence starts with `suite error:` as not red. Or give each of those six plants an `@part` (for example `CHK-M10-281@one refused frame`, `CHK-M10-205@process_vm_readv`, `CHK-M10-344v@no part of the token`, `CHK-M10-215@no accepted frame`, `CHK-M10-204@/run/docker.sock`).

3. **nit**: `agent/test/sandbox/sandbox.py:1032–1040`. `redact_like` uses Python `re` with the TS §8.6 patterns rewritten for Python (`\z` → `\Z`), not RE2. The patterns are repo constants and the input is the host's own sample output, so the RE2 invariant ("untrusted input or patterns") is not engaged. But a semantic difference between Python `re` and RE2 can show up as a false CHK-M10-222 diff. Using `google-re2` (`python3-re2` is not in the archive) or comparing before redaction would remove the approximation.
