## Checks
1. **Authorisation (security invariants; TS L1084, L1103–L1106).**
   - Upload: `require_role("admin")`, a session or an API token. It isn't a sensitive action, so there's no TOTP-session check and no sink gate. The plant that added them is red.
   - Delete and rebuild: `require_totp_session()`, an admin TOTP-verified session behind the sink gate. API tokens are refused, and so is a request after 15 minutes of sink outage (#1).
   - `GET /tasks/{id}`: admin, session or token.
   - All of them sit in the user router, so `bsa_` and `bse_` get 401.
2. **Order of checks (builder checklist 4).**
   - The upload declares no body, so auth and role run before a byte is read (0 bytes pulled on refusal), and the body is then read through the `bit` cap.
   - The rebuild POST declares no body.
   - Ids are checked before any cast: digits only for the policy id, and only the 8-4-4-4-12 form for the task id (checklist 5).
3. **Upload parsing (#99 (c), TS L522, L1137–L1138).**
   - The body is parsed in memory with python-multipart's low-level parser, and nothing is spooled (the spool spy proves it).
   - It allows one `file` part, 16 headers, 8 KiB header values and a 5 MiB part. A larger part, or a larger body, gives 413 with no row.
   - Every 400 is one fixed text and never echoes input (the canary sweep proves it).
   - The client name is metadata in the #99 (d) form, and never a path or a log line.
4. **Answers (#98, #102 (d)).**
   - Upload: 200 for `success` and `rejected`, with `errors` as stored.
   - Delete: 204, 404, 409 `conflict`, 409 `policy_managed_on_server`. `delete_policy` passes `refuse_server_folder=True`.
   - Rebuild: 202 `{task_id}`.
   - During start-up, 503 `about:blank` with `Retry-After: 10`. Disk and database errors give 503 (#98 (j)), including the stale-temp `FileExistsError` (the TASK-155 carry).
   - `TaskItem` documents `removed_leftovers` and `not_imported`, which closes the TASK-157 carry.
5. **Layering.** Handlers only authorise, parse HTTP and map exceptions to answers. The work is done in `CatalogService` (TASK-160) or in a read-only repository read (the `GET /audit-log` precedent). No route runs or queues a command, edits plugins or changes host settings.

## Findings
None blocking or should-fix.

1. nit, `policy_import.py:193`: `parse_upload` runs on the event loop. For a 5 MiB body that holds the loop for a few milliseconds. `run_in_threadpool` around it, as for the import itself, would keep the loop free.
2. nit, `policy_import.py:112`: `header_end` counts distinct header names, so a repeated header doesn't add to its own count. The parser's `max_header_count=16` still bounds the total, so nothing is unbounded.
