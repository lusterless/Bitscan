### Findings
1. nit, `.github/workflows/release.yml:324-330`. The web SBOM is not byte-reproducible.
   - **Cause:** `npm sbom` writes a random `serialNumber` and a `metadata.timestamp` on every run. I ran it twice here with npm 11.19.1: the files differ at `serialNumber`.
   - **Why the test missed it:** the tester's "identical bytes" result for the web SBOM comes from the npm shim, which replays one recorded output.
   - **Assessment:** nothing requires it. TS §3.1 L177 asks for reproducible Go builds, which G39 covers, and the Python SBOM is deterministic as its comment says. The workflow makes no claim about the web file.
   - **Fix (optional):** leave it. If byte-stable release files are wanted later, rewrite `serialNumber` and `timestamp` in a `python -I` post-step. Until then, don't state that both SBOMs are reproducible.
