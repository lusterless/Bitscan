## Checks
1. **Plain text (TS §6.3 L1141; security invariants).**
   - Every API value renders as a JSX text node; `execute` sits in a `<pre>` as text.
   - My grep of `web/src` (tests excluded) finds no `dangerouslySetInnerHTML`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `fetch(` or browser storage. The tester's source scan checks the same list (CHK-M7-391).
   - Hostile values render literally on every screen (CHK-M7-392).
2. **Client and token.**
   - Every call goes through the generated `api` client. The upload passes a `FormData` with one `file` part through `bodySerializer`, so the browser sets the boundary, and there is no hand-written `fetch`.
   - The token stays in memory and is never put in a URL, a body or storage (CHK-M7-393).
3. **Sensitive actions (TS §6.2 L1084).** On `totp_session_required`, delete and rebuild offer only "Sign in again". There is no API-token field and no retry with another credential (CHK-M7-371 a and b).
4. **Roles (REQ-183 (3)).**
   - Profiles and profile detail are open to every role. Upload, Import history and Rebuild are admin only.
   - A route the role may not open renders only "Not available" and sends no request (plants 400 and 401).
   - Detail actions show only for an admin on a live policy (plants 398 and 399). The server still enforces every rule.
5. **Contract.**
   - The PATCH bodies are exactly the REQ-168 forms. Delete is one `DELETE` after a confirmation. The rebuild polls `GET /tasks/{id}` every 2 s until `succeeded` or `failed`, stops on a refusal or on unmount, and shows every `TaskResult` field.
   - The start-up 503 maps only on its four exact markers. The shown texts are fixed constants, never built from response text.
   - The display name is the API's `display_name` from `v_plugin` (TS §1.4).
