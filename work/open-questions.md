# Open questions for the spec owner, and process decisions for the user

The 2026-10-19 workspace audit collected these. Only the planner edits this file. The file is self-contained: the audit ids in the tables (P-, R-, S-, T-, I-, R2-*, R3-*) are history only. They refer to reports in `work/audit/archive/`, which are history and need not be read unless someone asks. It has five parts:
1. Numbered spec questions (#1 onwards).
2. Every **Open spec question** marker that is in `.claude/` now.
3. The spec's own open questions (TS §8.5).
4. Process decisions for the user, which are not spec questions.
5. Spec-internal inconsistencies, reported only; the spec is never edited here.

This file is not guaranteed to be complete. `grep -rn "Open spec question" .claude` gives the current markers; part 2 was rebuilt from that grep in round 3. Entries are never renumbered or reused, and a withdrawn entry keeps its number.

Status values:
- **agreed**: the author and one confirmer agree it is an open question, so a rule may carry a marker that points at it.
- **proposed**: it still needs a confirmer, and no rule marker may point at it.
- **withdrawn**: rejected as a question. It keeps its number, and no marker may point at it.

None of these has been answered. When the owner answers one:
1. Record the decision in `work/decisions.md`.
2. The `.claude/` writer replaces the rule's marker line (the line that points at `#N`, or the part-2 "own question" line) with the decided behaviour.
3. The planner marks the entry "answered, D-##".

### M2 re-check of the questions flagged for M2 (planner, 2026-10-21)

- **#5** (health prefix and authentication; metrics route). Still open. Blocks TASK-044 (W4) and the path check of TASK-047. The recommended default stands: `/healthz` and `/readyz` outside `/api/v1`, no token, no rate limit, security headers still sent; a 200 body `{"status": "ok"}` and a 503 problem-details body that names the failed check (db, migrations or system_schedule) and nothing else. The metrics route is not needed in M2: only `bitscan_alerts_total{kind}` exists, unexposed (REQ-055 (3)); the route can wait for M3, where the other metrics arrive.
- **#7** (initial password). Still open, and the suggested answer needs one change: "a forced change at first sign-in" cannot be stored, because `app_user` (TS §5.2 L953–L964) has no column for it and M2 must not change the schema. Recommended: `users create-admin` prompts twice on a TTY (input hidden, both must match, at least 12 characters) and, with no TTY, reads one line from stdin; the password is never an argument or environment value (shell history, `ps`). `POST /users` takes an initial password in the body (REQ-041 rules); there is no forced change, and the UI offers a change. Blocks TASK-042 (W4) and TASK-046 (W9).
- **#24** (vault product and API; sink wire format). Still open, and it gained a sub-question: the TS §8.7 manager unit (L1362–L1371) loads no credential for the sink, so an HTTPS sink cannot have a secret token without either the vault or a unit change (the units are verbatim from the spec). Recommended: HashiCorp Vault, Transit engine (`BITSCAN_TOTP_KEY_REF` is the transit key name; the seed is encrypted and decrypted through `POST /v1/transit/encrypt|decrypt/<key>`, so the key never leaves the vault), token auth from `BITSCAN_VAULT_TOKEN_FILE`, TLS verified against the system CA store. Sink: `BITSCAN_AUDIT_SINK` is either `syslog+tls://host:port` (RFC 5424 message, octet-counted framing per RFC 5425, server certificate verified, no client credential) or `https://…` (one JSON object per entry, `POST`, no credential unless the owner names one in the vault). Plain `udp`, `tcp` and `http` are refused. Blocks TASK-032 (W2), TASK-030 (W3) and TASK-034.
- **Alert thresholds** (the two own-question markers `auth-and-users.md:31` and `audit-and-alerts.md:27`). Now numbered **#54**. Blocks the alert parts of TASK-036 and TASK-038 (W3, W5). "Floods of 409 result posts" is M3.
- **#8** (`DELETE /api-tokens` with an API token). Still open; blocks one criterion of TASK-041 (W8). Default unchanged: allowed, own tokens only.
- **#34** (OpenAPI document served). Still open; M2 keeps the M0 reading (not served), so it blocks nothing. The lead should confirm it before the first route lands (W5), because the first routes make the question visible.
- **#1** (`DELETE /policies/{id}` during a sink outage). Not M2 work; TASK-037's TOTP-session dependency is written so that M7 can apply or skip the sink gate for that route once #1 is answered.
